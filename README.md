# 雀魂 rating 批量跑谱 + 战绩图表

输入一个雀魂 ID（UID 或昵称）和要查询的场次，程序自动：

1. 从 **雀魂牌谱屋**（amae-koromo）拉取该玩家最近的对局列表（可按场次类型筛选），并生成一份战绩概览；
2. 逐局提交到 **mjai.ekyu.moe**，用 **Mortal 4.1b** 跑谱，取回每局的 **分数（rating）** 和 **AI 一致率**；
3. 输出明细 CSV + 一张图，**跑完自动弹出图片窗口**：
   - **上图**：rating 曲线 + AI 一致率曲线 + **平均 rating 虚线**
   - **下图**：每局 **段位分变化（±pt）** 柱状 + **段位分走势**曲线
   - **右侧**：战绩概览（最近 N 场 与 总体 两套数据）

## 安装

```bash
pip install -r requirements.txt     # playwright + matplotlib
```

本机需要装 **Edge 或 Chrome**（脚本会自动找，找不到可以直接改脚本里的 `BROWSERS` 列表）。
Windows 上一般自带 Edge，无需额外安装。

## 用法

### 最省事：双击 `run.bat`

双击文件夹里的 **`run.bat`**，按提示依次输入：

1. 雀魂 UID 或昵称（UID 就是牌谱屋网址里 `.../player/12345678/12` 的 `12345678`）
2. 跑最近多少局（直接回车 = 20）
3. 场次类型（直接回车 = 玉）

然后等着就行。跑完会自动弹出图片，结果都在 `rating_out` 文件夹里。

### 或者用命令行

```bash
# 最近 20 局玉之间
python mahjong_rating.py --id 12345678 --games 20 --mode 玉

# 也可以直接用昵称
python mahjong_rating.py --name 示例玩家 --games 30 --mode 玉

# 多个场次一起跑（合并后按时间取最近 N 局）
python mahjong_rating.py --id 12345678 --games 40 --mode 玉 --mode 玉东
```

| 参数 | 说明 |
| --- | --- |
| `--id` / `--name` | 雀魂 UID 或昵称（二选一，必填） |
| `--games` | 跑最近多少局，默认 `20` |
| `--mode` | 场次类型，可重复使用，默认 `玉`。支持：`王座 玉 金 王东 玉东 金东 三王座 三玉 三金 三王东 三玉东 三金东` |
| `--concurrency` | 同时开几个页面提交，默认 `3`（实测调到 6 以上会有大半卡在人机验证，别贪多） |
| `--out` | 输出目录，默认 `rating_out` |
| `--no-show` | 跑完不自动弹出图片窗口 |
| `--fresh` | 连跑谱缓存一起清掉，全部重新跑 |

## 输出

| 文件 | 内容 |
| --- | --- |
| `rating_<UID>.png` | 主图。左：上=rating/AI一致率（每个点标分数）、下=每局 ±pt 与段位分走势（标出**最高/最低/最近**）；右：战绩概览；右下角一只吉祥物 |
| `rating_<UID>.csv` | 明细：时间、场次、顺位、点数、段位分变化、分数、AI 一致率、牌谱链接 |
| `summary_<UID>.txt` | 右侧那段概览文本（纯文本版） |
| `results.json` | 跑谱结果缓存，**支持断点续跑**（中断后重跑同一条命令会自动跳过已完成的局） |
| `.browser_profile/` | 浏览器配置目录，删掉不影响使用（人机验证偶尔要重置就删它） |

**每次运行都会先清掉上一次的同名结果文件**（png / csv / txt），免得新旧混在一起；
`results.json` 默认保留（这样中断后还能续跑），加 `--fresh` 可以连它一起清掉、彻底重跑。

## 几个说明

**为什么要开浏览器？** 牌谱屋和 mjai.ekyu.moe 都对抓取/提交加了 Cloudflare 验证，纯 HTTP 脚本拿不到数据。
但用 Playwright 直接启动的浏览器会被判定为自动化环境、验证过不去；所以脚本的做法是
**自己启动一个普通的 Edge/Chrome（带调试端口），再用 CDP 接进去操作**——这样验证码可以静默通过。
运行时会弹出一个浏览器窗口，**请不要手动关掉它**，程序结束时它会自己关闭。

**速度**：跑谱本身要排队 + 计算，一局大概 1~3 分钟。程序把流程拆成两阶段：

1. **提交**：同时开 `--concurrency` 个页面过验证、把任务号拿到（这一步占浏览器，比较快）；
2. **等结果**：所有任务**并行**等，谁先好谁先出。

所以总耗时 ≈ 提交用时 + 最慢那一局的跑谱时间，而不是一局一局加起来。
另外**已提交的任务号会存进缓存**，中途停掉再跑，这些局直接取结果，不用重新过验证。

**关于并发**：实测**并发 3 最稳**，调到 6 会有一半以上卡在人机验证，调到 10 基本全挂——
Cloudflare 对「同一个 IP 同时来一堆验证请求」很敏感，这是服务端策略，本地绕不开。
另外浏览器默认会节流后台标签页（表现为"只有正开着的那个页面在动"），脚本已经用启动参数关掉了这个节流。

**失败就跳过**：某局失败（验证超时、限流等）不会阻塞其它局，直接跳过并在末尾列出来。
被跳过的局不会从图里消失：上图把它们的位置**断开并打一个灰色 ✕**，图例写「跑谱失败 N 局(已跳过)」，
右侧概览也会写「跑谱成功 X/Y 局，失败 N 局(已跳过)」。补跑只要重跑同一条命令，只会补缺的那几局。

**浏览器残留**：程序结束（包括 Ctrl+C）会关掉自己启动的浏览器。
万一 profile 还被占着（上次没退干净），程序**不会去杀任何进程**，而是换一个备用 profile 目录启动，
免得误杀你正在跑的另一个实例。启动不了时手动关掉本程序遗留的 Edge/Chrome 窗口再跑即可。

**场次能跑多少**：牌谱屋接口单次只返回 150 局，脚本会自动**向下滚动加载**更早的对局，
所以 `--games 400` 也能取满；但牌谱屋本身只收录最近的数据，再早就没有了。
局数越多当然越久，量力而行（也可以分几次跑，比如每次 20 局）。

**分数口径**：图中的 rating 就是复盘页面 About 里显示的「分数」，等于 mjai 报告里的 `review.rating × 100`；
AI 一致率等于报告里的 `total_matches / total_reviewed`。两者都由 Mortal 4.1b 在线上服务端算出，
与你在网页上手动跑同一局得到的结果一致。

**注意**：Mortal 4.1b 的模型权重官方并未公开（`Equim-chan/Mortal` 仓库没有任何 release），
所以本地无法复现同样的分数——本项目走的是官方线上服务，这也是唯一能拿到 4.1b 分数的途径。
另外 rating 本身波动很大（官方 FAQ 明说它「不是一个可靠的指标」），看趋势比看单局更有意义。

**概览与 pt 的口径**：

- 「最近 N 场」那一块，是把最近 N 局里最早那局的开始时间当起点，去查 `player_stats` /
  `player_extended_stats` 得到的——所以它和「总体」是同一套统计口径，只是时间范围不同。
- 段位、最高段位、对战数、1~4 位率、均顺来自牌谱屋 `player_stats`；和牌率/放铳率/副露率/立直率
  来自 `player_extended_stats`；「近 1 日/周/月」是分别查三个时间段的场数。
- 「每局段位分变化（±pt）」直接用牌谱屋对局记录里的 `gradingScore`，是雀魂官方的本局段位分增减，
  所以玉之间的 4 位可能是 -190pt、3 位 -9pt 这种量级。
- 「段位分走势」是从**当前段位分**往回逐局减去 `gradingScore` 反推出来的；如果这段区间里升过段或掉过段，
  分数会被雀魂重置，曲线会在那里**断开**（不画那一段），避免给出错误数字。
- 「安定段」是**简易估算**，口径和牌谱屋统计面板里的「安定段位」不一样：这里只是拿最近 N 局实测的
  平均每局 pt 判断走势，并在为正收益时顺带估算「预计多少战后升段」。想看去掉这段可以直接删掉
  `stability_lines()` 这一项。

## 常见问题

- **一直卡在「提交中」**：Turnstile 没通过。关掉输出目录里的 `.browser_profile` 重跑一次通常就好。
- **某个玩家查不到**：牌谱屋只收录排位对局，且需要该玩家近期有对局。
- **提示「没有取到任何对局」**：换一个 `--mode` 试试（比如他只打玉之间，却传了 `--mode 金`）。
- **想换模型版本**：把脚本里的 `MODEL_TAG = "4.1b"` 改成 `4.1c` / `4.1a` / `4.0` / `3.0` 即可。
